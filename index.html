Guide pratique · Power BI · Cursor

Développer un rapport Power BI avec Cursor : le workflow PBIP qui tient la route

Utiliser Cursor et les skills Microsoft pour construire un rapport Power BI, l’afficher dans Desktop et en vérifier les chiffres.

Dans ce guide, on utilise Cursor, un éditeur de code doté d’un agent IA, avec deux skills publiés par Microsoft pour Power BI. Un skill est un guide que l’agent suit : il lui apprend à travailler sur un projet Power BI comme le ferait un développeur expérimenté.

Concrètement, les skills permettent à Cursor de :

  • construire un rapport complet à partir d’une demande métier : pages, visuels, filtres et thème ;
  • ajouter ou corriger des mesures DAX dans le modèle ;
  • ouvrir le résultat dans Power BI Desktop et en faire des captures ;
  • vérifier que les chiffres affichés sont justes, et corriger tant que ce n’est pas le cas.
Au programme
  1. Comprendre : le format PBIP, les skills et le serveur MCP.
  2. Pas à pas : les outils nécessaires, préparer le projet, installer les skills, puis passer une première demande à Cursor.

Partie 1 · Comprendre

Le format PBIP : un rapport sous forme de fichiers

Un fichier .pbix est pratique pour un utilisateur final, mais il est peu adapté au travail assisté par un agent : son contenu n’est pas directement lisible ni versionnable comme du code. Avec PBIP (Power BI Project), le projet est enregistré dans un dossier sous forme de fichiers texte :

  • le modèle sémantique (tables, relations, mesures DAX) dans des fichiers .tmdl ;
  • le rapport (pages, visuels, filtres, thème) dans des fichiers .json.

Cursor peut alors les lire, les modifier et les comparer, tandis que Power BI Desktop recharge les changements.

Les deux skills et les outils qu’ils appellent

Chaque skill indique à Cursor la méthode à suivre et les outils à appeler.

powerbi-report-cli : le rapport

Cursor écrit les pages et visuels dans les fichiers JSON du rapport. Le skill fait ensuite appel à powerbi-report-author, un outil en ligne de commande, pour valider ces fichiers, ouvrir le projet dans Power BI Desktop et faire des captures des pages.

semantic-model-authoring : le modèle

Pour les mesures et les tables, le skill fait appel au serveur MCP Power BI Modeling, qui modifie le modèle et exécute des requêtes DAX. Sans MCP, Cursor modifie directement les fichiers .tmdl.

Le serveur MCP, c’est quoi ?

Un serveur MCP est un connecteur qui donne à Cursor des actions qu’il peut exécuter lui-même. Ici, le serveur Power BI Modeling se connecte au modèle ouvert dans Power BI Desktop : il sert à lire et modifier tables et mesures, et surtout à exécuter des requêtes DAX pour obtenir les vrais chiffres. Il est installé en même temps que les skills.

Résultat : Cursor construit le rapport, le capture, puis compare les chiffres affichés aux résultats des requêtes DAX. Il corrige jusqu’à ce que les deux concordent.

Partie 2 · Pas à pas

Ce qu’il vous faut

Power BI Desktop

La version standard, à jour, installée depuis le Microsoft Store ou le site de Microsoft. La version « optimisée pour Power BI Report Server » ne prend pas en charge les projets PBIP.

Cursor

L’éditeur installé sur votre poste, avec un compte connecté pour utiliser l’agent.

À installer également :

  • Node.js : le serveur MCP Power BI Modeling est lancé avec la commande npx, fournie par Node.js ;
  • APM (Agent Package Manager) : c’est l’outil qui fait fonctionner la commande apm install de l’étape 2. Il s’installe une seule fois sur le poste, avec cette commande PowerShell :
irm https://aka.ms/apm-windows | iex
Attention : créez le dossier du projet sur votre disque local, pas dans un dossier synchronisé OneDrive ou SharePoint. Microsoft indique que la synchronisation peut faire échouer l’enregistrement des projets PBIP.

Étape 1 : enregistrer le rapport au format PBIP dans le dossier du projet

Au préalable, créez dans Power BI Desktop les tables utiles, déjà connectées aux données. Cursor pourra ensuite modifier Power Query, le modèle et le rapport. Enregistrez ce fichier dans un dossier projet via Fichier > Enregistrer sous > Projet Power BI (.pbip), puis ouvrez ce dossier dans Cursor. Vous devez obtenir une structure de ce type :

MonProjet/
├── MonRapport.pbip                  ← fichier à ouvrir dans Power BI Desktop
├── MonRapport.Report/               ← le rapport (fichiers JSON)
│   └── definition/
│       ├── report.json
│       └── pages/
│           └── <page>/
│               ├── page.json
│               └── visuals/<visuel>/visual.json
└── MonRapport.SemanticModel/        ← le modèle (fichiers TMDL)
    └── definition/
        ├── model.tmdl
        ├── relationships.tmdl
        └── tables/
            └── Ventes.tmdl

Étape 2 : installer les skills dans le dossier du projet

Installation au niveau du projet : les skills et le serveur MCP sont installés uniquement dans ce dossier. Ils ne sont disponibles dans Cursor que lorsque ce dossier est ouvert, et pas dans vos autres projets. Il est aussi possible de les installer pour tous les projets Cursor, mais c’est une autre configuration que nous ne verrons pas ici.
  1. Ouvrez le dossier racine du projet PBIP dans l’Explorateur de fichiers.
  2. Dans ce dossier, ouvrez PowerShell : clic droit dans le dossier, puis « Ouvrir dans le Terminal » / « Ouvrir PowerShell ici ».
  3. Exécutez la commande suivante. APM installe à la fois les skills sélectionnés et la configuration des serveurs MCP associée, pour la cible Cursor.
apm install microsoft/skills-for-fabric `
  --skill semantic-model-authoring `
  --skill powerbi-report-cli `
  --target cursor

Cette commande installe notamment :

  • semantic-model-authoring : le cadre pour travailler le modèle sémantique ;
  • powerbi-report-cli : le cadre pour concevoir, créer et vérifier le rapport ;
  • les enregistrements MCP que Cursor doit reconnaître.

Microsoft précise que l’installation place les skills dans le projet et enregistre les serveurs MCP pour l’outil cible. Tous les serveurs MCP Fabric déclarés par le package sont installés ; le filtre --skill limite les skills activés, pas les serveurs MCP.

Étape 3 : ajouter une intention graphique

Dans le projet, créez par exemple un dossier design. Le nom n’a pas d’importance : l’essentiel est de le citer dans votre demande. Vous pouvez y placer :

  • theme.json, votre thème Power BI ;
  • une ou plusieurs captures d’écran de référence ;
  • un court document de règles : couleurs, police, usages attendus, indicateurs à mettre en avant.

Ce dossier ne remplace pas la consigne : il rend la consigne vérifiable. Au lieu de demander « fais un beau rapport », on indique à Cursor les fichiers à lire et l’objectif de chaque page.

Étape 4 : activer et tester le serveur MCP dans Cursor

  1. Ouvrez le dossier du projet dans Cursor.
  2. Dans la barre latérale, ouvrez Customize, puis la section MCPs.
  3. Vérifiez que le serveur Power BI est visible et activé. Selon la politique de l’entreprise, une première autorisation peut être demandée.
  4. Dans le chat, demandez : Peux-tu vérifier que le serveur MCP Power BI est disponible et me dire quels outils il expose ?

Cursor demande normalement une validation avant d’exécuter un outil MCP. Prenez le temps de lire l’action proposée : un MCP est capable d’accéder à des outils externes et peut exécuter des opérations pour vous.

Pour tester, demandez par exemple : Exécute une requête DAX qui compte les lignes de la table des sessions.

Étape 5 : vérifier l’ouverture de Power BI Desktop

Demandez à Cursor : Ouvre ce projet dans Power BI Desktop. Cette étape confirme que Cursor pourra afficher et contrôler le rendu final.

Si l’outil ne trouve pas l’exécutable de Desktop, ajoutez la variable d’environnement Windows PBI_DESKTOP_PATH avec le chemin réel de votre installation, puis redémarrez Cursor. Exemple :

PBI_DESKTOP_PATH = C:\Program Files\WindowsApps\Microsoft.MicrosoftPowerBIDesktop_2.158.1304.0_x64__8wekyb3d8bbwe\bin\PBIDesktop.exe
Attention : ne copiez pas ce chemin sans le vérifier. Le numéro de version et le dossier peuvent être différents sur votre poste. Utilisez le chemin de votre propre PBIDesktop.exe.

Étape 6 : passer une première demande à Cursor

Le modèle choisi dans Cursor a un impact réel sur la qualité du raisonnement et des itérations. Préférez, lorsque votre licence le permet, un modèle solide pour les tâches de conception et de code. Ensuite, donnez un maximum de contexte : objectif, utilisateurs, tables, définitions des KPI, contraintes visuelles et critères de réussite.

Crée une page « Synthèse des ventes » avec le thème design/theme.json. Affiche le chiffre d’affaires, le nombre de commandes, l’évolution mensuelle du chiffre d’affaires et le top 10 des produits. Ajoute un filtre par année.

Si Power BI Desktop affiche la bannière « Apply external changes », cliquez dessus pour charger les modifications de Cursor. Enregistrez d’abord vos éventuels changements faits dans Desktop : ils seraient sinon remplacés.

Bon réflexe : restez disponible pendant l’exécution. Cursor peut vous demander une précision métier, une autorisation d’outil ou une validation de modification. Les meilleurs résultats viennent d’un aller-retour court entre l’agent et l’expert métier.
